Promo Studio turns an app's screenshots and a short brief into a promo video in four sizes: landscape, vertical, square and portrait. Each render is versioned, and you get files ready to post. This guide covers everything from first setup to delivery.

Studio as an app

Menu 1 opens the editor at localhost:3100 in its own window using Edge, Chrome, Brave or Chromium. When you close the window, Studio stops too.

Desktop shortcut

Menu d adds a shortcut with the app icon. One click opens straight into the Studio window.

Moving computers?

Copy the whole folder, including promo-studio/inbox/ and promo-studio/out/, then run setup again. It rebuilds the parts specific to each operating system.

A Git clone excludes ignored original media and generated outputs. Copy promo-studio/inbox/ and promo-studio/out/ separately if you need those files on the new machine. The old numbered media folders in the workspace root are historical and stay untouched.

How work flows

Five stations, left to right

All paths below are inside promo-studio/. Each folder holds one stage of the work. Files only move forward, and nothing in a later station is overwritten. Every render gets a new version number.

inbox/<app>/

Intake

Raw client files: screenshots, logo, music, notes.txt. These are never edited.

projects/<app>/brief.json

Brief

The single source of truth: copy, colors, font, features, timing, formats.

out/renders/<app>/v001

Render

Master MP4s, thumbnails, and a frozen copy of the brief used. _drafts/ holds quick previews.

out/delivery/<app>/

Deliver

Upload-ready MP4s at −14 LUFS with fast-start, GIF previews, a contact sheet and a manifest.

out/archive/

Archive

A zip of the brief, assets, renders and deliveries. The originals stay where they are.

Prepared media lives in promo-studio/public/projects/<app>/; preview stills go to promo-studio/out/frames/. Visual QA goes under promo-studio/out/renders/<app>/_qa/.

Autopilot · launcher w

Drop the files. Pre-production runs itself.

Make a folder per app in promo-studio/inbox/ and drop in the screenshots, a logo and a notes.txt. The autopilot waits until copying finishes, then works through every step below on its own. A typical app takes about 2–3 minutes.

Create project→Prep assets→Logo colors→AI brief→Hook variants→Voiceover→Vertical draft→Visual QA→Report

What to drop

  • Screenshots, named in feature order: 01-home.png, 02-plans.png…
  • The logo: any image with logo in its file name. Its colors are measured automatically.
  • notes.txt: real facts about the app, like features, website and offers. The AI never invents stats.
  • Music (optional): an mp3, wav or m4a, volume-matched automatically.

What you get back

  • brief.json, hooks.md and voiceover.md in promo-studio/projects/<app>/
  • A vertical draft video in promo-studio/out/renders/<app>/_drafts/
  • A QA score with fixes, and autopilot-report.md listing what to check
  • Edit a brief by hand and later runs leave it alone, unless you choose w → 3

Walkthrough

Your first promo, step by step

This is the manual route, for when you want to control each step. Each step shows its launcher key and the terminal command (run commands inside promo-studio/).

  1. Create the project

    Choose a short slug in lowercase with hyphens, like fit-tracker, and the app's display name. Promo Studio creates the brief, the asset folders and an inbox folder, then opens the inbox for you.

    Launcher 2 · or
    $ npm run new -- fit-tracker "Fit Tracker"

  2. Drop the client files in the inbox

    Put screenshots in promo-studio/inbox/fit-tracker/ and name them so they sort in feature order (01-home.png, 02-plans.png…). Any file with logo in its name is used as the logo. A notes.txt with facts about the app gives the AI real material to write from.

  3. Prepare the assets, or let AI draft everything

    Manual: launcher 6 resizes the screenshots (max 2400 px tall), trims the logo and evens out the music volume, then links them into the brief.

    With AI: launcher a → 1 does that prep and then writes the whole brief from your screenshots and notes. Review its "Check before rendering" note.

    $ npm run tools -- prep-screens fit-tracker --apply
# or the AI route:
$ npm run ai -- brief fit-tracker --url https://fittracker.app

  4. Polish the brief

    Open promo-studio/projects/fit-tracker/brief.json and adjust the copy, colors or timing. If Studio is open, it reloads as soon as you save. See the brief reference below.

  5. Preview in Studio

    Launcher 1 opens the app window. In the sidebar under Projects → fit-tracker you'll find one composition per format. Press space to play, and drag the timeline to scrub.

  6. Draft, then final render

    A draft (3) renders at half resolution into promo-studio/out/renders/fit-tracker/_drafts/, so you can review it quickly. A final render (4) writes full-quality masters into a new v001, v002… folder under promo-studio/out/renders/fit-tracker/, never over an old one.

    $ npm run draft -- fit-tracker --formats 9x16
$ npm run render -- fit-tracker

  7. Deliver and archive

    5 turns the latest version into upload-ready files in promo-studio/out/delivery/. When the project is done, 7 zips everything into promo-studio/out/archive/.

    $ npm run deliver -- fit-tracker            # or --version v002
$ npm run tools -- archive fit-tracker

brief.json reference

One brief, four formats

Everything the video says and looks like lives in this one file. Asset paths are relative to promo-studio/public/. Leave a path empty to get a built-in placeholder: a letter badge instead of a logo, or a branded app screen instead of a screenshot.

{
  "formats": ["16x9", "9x16", "1x1", "4x5"],
  "props": {
    "appName": "Fit Tracker",
    "tagline": "Train smarter.",
    "logo": "projects/fit-tracker/logo.png",
    "brand": { "primary": "#…", "secondary": "#…", "background": "#…", "text": "#…", "font": "Inter" },
    "hook": { "headline": "≤ 6 words", "subheadline": "≤ 8 words" },
    "features": [ { "title": "≤ 4 words", "description": "≤ 12 words", "icon": "emoji", "screenshot": "projects/…/screens/screen-01.png" } ],
    "stats": [ { "value": 4.8, "prefix": "", "suffix": "★", "label": "Average rating" } ],
    "cta": { "headline": "…", "button": "Download free", "url": "fittracker.app" },
    "audio": { "music": "projects/fit-tracker/audio/music.m4a", "volume": 0.6 },
    "timing": { "hookSeconds": 3, "featureSeconds": 3.5, "statsSeconds": 3, "ctaSeconds": 3.5, "transitionFrames": 15 }
  }
}
KeySizeUse it for
16x91920 × 1080YouTube, website, LinkedIn
9x161080 × 1920Reels, TikTok, Shorts, Stories (keeps clear of on-screen buttons)
1x11080 × 1080Feed posts
4x51080 × 1350Instagram/Facebook feed ads

Rules that keep it working

  • 1–6 features and up to 4 stats. The stats scene only appears when you add stats.
  • Fonts: Inter, Poppins, Montserrat, Space Grotesk, DM Sans, Plus Jakarta Sans.
  • The video length comes from timing (30 fps). Transitions overlap neighbouring scenes.
  • Only use stats you can prove. Promos are real advertising.
  • Each AI rewrite saves the old brief in history/ first.
  • Captions: once the project has a voiceover (a → 3 or the autopilot), its lines appear as moving captions in your brand colour. Add "captions": false next to "formats" to hide them.
AI assistant · launcher a

Two kinds of help

The Claude API tools are repeatable, fixed jobs you pay for per run. The agents handle open-ended edits and run on the Claude or ChatGPT plan you already have.

Claude API · needs a key

Fixed jobs

  • Auto-brief 1: screenshots, logo, notes and website → a complete brief.
  • Hook variants 2: five opening lines for A/B tests, optionally as separate projects.
  • Voiceover 3: narration sized to each scene's length.
  • Visual QA 4: renders every scene and format and gives a score with fixes.

Add your key with a → k. It's saved to promo-studio/.env. Each run prints its cost and logs it in ai-log.jsonl, typically $0.05–0.30.

Your subscription · no key

Ask an agent

  • Ask Claude Code 5: describe a change and it edits briefs and templates.
  • Ask Codex 6: the same, using your ChatGPT plan.
  • Chat with Claude c on the home screen (or 7 here): a conversation in the same window, already briefed on this studio. Pick a project or n for a new app, then just ask: "take the brand colours from my logo", "make it vertical only". Type /exit to return.

Unattended requests can only edit briefs and templates. In the chat you're at the keyboard: brief edits and previews run straight away, anything bigger asks you first.

$ npm run ai -- status
$ npm run ai -- hooks fit-tracker --count 5 --create
$ npm run ai -- qa fit-tracker --formats 9x16
$ npm run ai -- ask "make the CTA button text bigger"

The AI only writes copy, colors, font and screenshot choices. Timing, formats, audio and logo stay yours. Every answer is checked against the template before it's saved, and the AI is told never to invent stats or claims.

Troubleshooting

If something goes wrong

Start with launcher 9 (Doctor). Most problems below show up there first.

Studio opened in a browser tab, not its own window

No Chrome, Edge, Brave or Chromium was found, so it fell back to your default browser. Install one of them, or point Promo Studio at a specific browser:

# macOS / Linux
$ PROMO_BROWSER="/path/to/chrome" ./promo-studio.sh studio
# Windows (PowerShell)
> $env:PROMO_BROWSER="C:\path\to\chrome.exe"; & ".\PROMO STUDIO.bat" studio
I copied the folder to a Mac or Linux PC and nothing works

Run bash setup.sh on the new computer. Some installed parts are specific to each operating system, so setup detects the move and rebuilds them. It also fixes the "can't run this file" permissions.

The autopilot skipped my brief

You edited brief.json by hand, so the autopilot keeps your version and only refreshes assets, hooks and voiceover. To replace it with a new AI draft, use w → 3 (Re-run one folder).

"No Claude API credentials found"

Create a key at console.anthropic.com, then use launcher a → k and paste it. The agents (5–7) don't need a key.

The text is cut off or crowds the phone mockup

Shorten that line in brief.json. The limits: headline 6 words, feature title 4, description 12. Then run Visual QA (a → 4) or render a few still frames to check:

$ npm run frames -- fit-tracker 9x16 60,150,300
Ask Claude Code refused to change a config or script

That's on purpose. Unattended requests can only edit briefs and templates. For a bigger change, chat with Claude (c) and approve each step yourself.

My render shows [placeholder] text, or looks like the sample

A new project starts with placeholder copy in square brackets. It shows up in the video until you replace it, and final renders refuse to start while any is left. Fill the brief in one of these ways: chat with Claude (c), drop screenshots and a logo in promo-studio/inbox/<project>/ and press w, use the AI brief (a → 1), or edit brief.json yourself.

My video has no captions

Captions come from the project's voiceover. Create one with a → 3. If you changed the number of features or removed the stats after writing it, the old voiceover no longer fits and captions switch off until you write it again. Also check that brief.json doesn't say "captions": false.

Setup says "Remotion Studio is running"

Setup reinstalls packages, and Windows can't replace files Studio has open. Close the Studio window (or press Ctrl+C where it runs) and run setup again.

Cloning the project on Windows fails with "Filename too long"

Some bundled Remotion skill files have long paths. Clone with long paths enabled:

> git clone -c core.longpaths=true <repo-url>
A new project doesn't show up in Studio

Project names must be lowercase with hyphens (my-app). Run npm run sync or restart Studio. Folders starting with _ are templates and are hidden on purpose.

Is it safe to upgrade Remotion?

Use launcher u and not a manual npm install. It backs up your versions, upgrades every Remotion package together, then checks that everything still works: every format renders, Studio opens and the briefs are valid. If anything fails, it rolls back on its own. Close Studio first.

Delivery fails with "ffmpeg not found"

Rendering uses Remotion's built-in FFmpeg, but the delivery helpers need FFmpeg installed on your system. Install it with the command in the Setup tab for your OS, then run Doctor (9) again.
